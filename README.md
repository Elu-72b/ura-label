# うらラベル(ura-label)

化粧品・シャンプー・ボディソープなどの成分を調べ、成分ごとの**注意度(刺激リスクの目安)**と**主な配合目的**を確認できる Web アプリです。手入力検索から始め、テキスト貼り付け、カメラ読み取りへ段階的に拡張します。

- 製品に点数は付けません。見るのは**成分ごとの目安**です
- 注意度の**判定基準を公開**し、成分ごとに**出典**を表示します
- AI が生成した情報には「**AI生成**」と表示します
- 無料で、**ログインなしで使えます**。ログインすると、気になる成分と検索履歴(保存するかどうかを選べます)を残せます
- 画像読み取りを実装する場合は、画像の送信先と保存の有無を明示します

> 注意度は本アプリ独自の参考指標です。成分の良し悪しを断定するものではなく、製品全体の評価でもありません。

## 開発の背景・このアプリに込めた思い

敏感肌や化学物質過敏症などの理由で、化粧品や日用品を選ぶことに不安を感じる人がいます。気になる商品を見つけても、「自分の体に合わないかもしれない」と考えて、試す前から購入を諦めることもあると思います。

私自身、成分表示を見ても、知らない成分が何のために配合されているのか、自分にとってどこに注意すればよいのかを判断するのは簡単ではないと感じています。

**「体に合わないかもしれないから、試してみたい商品を買わない」という選択を、少しでも減らしたい。**

うらラベルは、成分について知るための手がかりを提供し、一人ひとりが自分に合った商品を考えるためのWebアプリです。成分ごとの注意度とその判定基準、出典を確認できるようにすることで、利用者が情報を見比べ、自分で判断するための材料を増やすことを目指します。

ただし、成分単体の情報だけで、実際に肌や体に合うかどうかを断定することはできません。注意度は製品全体の評価や医学的な安全性判定ではなく、購入や使用を強制・推奨するものでもありません。**不安をあおるのではなく、判断に必要な情報へアクセスしやすくすること**を大切にしています。

## 主な機能

- 🔤 **成分名の手入力検索**:成分名から検索し、注意度・主な配合目的・説明・出典を確認できます
- 📝 **テキスト貼り付け**:通販サイトなどの全成分表示を貼り付け、成分ごとの情報をまとめて確認できるようにします
- 📷 **カメラ読み取り**:成分表の画像から成分名を読み取り、利用者が確認・修正してから解析できるようにします
- 🎨 **注意度の表示**:注意度1〜5を**数字と色**で表示します。色だけで情報を伝えないようにします
- 🔍 **成分の詳細**:成分名・注意度・主な配合目的・説明・出典を確認できます。AI が生成した情報には生成日を、管理者が手動で修正した情報には最終編集日を表示します
- 📖 **成分辞典**:登録済みの成分を五十音順の一覧で見られます。注意度や配合目的で絞り込めます

ログインしていなくても、上の機能はすべて使えます。ログインすると、次の機能が使えるようになります。

- ⭐ **気になる成分**:気になる成分を登録し、一覧で確認したり、結果画面で目立たせたりできます
- 🕘 **検索履歴**:調べた成分名を履歴に残せます。**保存するかどうかは自分で選べます**(初期設定は「保存しない」)。履歴は1件ずつ、またはまとめて削除できます
- 👤 **マイページ**:メールアドレスとパスワードの変更、退会ができます

### 競合調査から見えた開発方針

成分を検索したり、成分表をスキャンしたりする機能だけでは、既存アプリとの差別化は難しいと考えられます。うらラベルでは、機能の多さよりも、**判定基準の公開・出典の提示・AI生成情報の明示・製品全体の評価と混同させない説明**を軸にします。

また、注意度の数字や色は分かりやすさのための独自指標であり、個人にとっての刺激やアレルギーの発生を予測・保証するものではありません。この限界を画面上でも伝え、利用者が自分の経験や必要に応じて専門家から得た情報とあわせて判断できる設計を目指します。

## 注意度(刺激リスクの目安)

| 注意度 | 色 | 目安 |
| --- | --- | --- |
| 1 | 🟢 緑 | 公的リストで懸念の記載がなく、長年広く使われている基礎成分 |
| 2 | 🟡 黄緑 | 一般に刺激性が低いとされるが、ごく稀に刺激・アレルギーの報告がある |
| 3 | 🟨 黄 | 旧表示指定成分に該当する、または肌質・体質によって刺激やアレルギーの可能性が指摘されている |
| 4 | 🟠 橙 | 旧表示指定成分に該当し、かつ刺激・アレルギーの報告が比較的多い |
| 5 | 🔴 赤 | 公的機関(EU 等)で配合濃度や用途の制限があり、注意喚起が多い |

- 判定の根拠が不明な成分は、断定せずに**注意度3**とします
- 判定基準と判定フローの詳細は [docs/CAUTION_CRITERIA.md](docs/CAUTION_CRITERIA.md) を参照してください

## 開発ロードマップ

実装は次の優先順位で進めます。

1. **成分DB・検索・注意度表示**を完成させる。手入力検索を最初の入口にする
2. **AI生成情報と出典の表示**を実装する。注意度に加えて、主な配合目的も表示する
3. **取得失敗・成分名の誤認識を安全に扱う**。曖昧な候補を別成分として断定せず、確認・修正できるようにする
4. **出典内容の自動検証**を、実現可能な範囲で追加する
5. **ログインして使える機能**(気になる成分・検索履歴)を追加する。避けたい成分などの個人ルールは、必要性を確認しながら検討する
6. **管理者による成分情報の編集**を追加する。AI が生成した内容を管理者が確認・修正できるようにする

入力方法は、手入力検索から始め、テキスト貼り付け、カメラ読み取りの順に拡張します。カメラ読み取りを追加する場合も、読み取り結果をそのまま確定せず、利用者が確認・修正できる流れにします。

## 情報の取得・表示方針

- まずデータベースを検索し、登録済み情報があれば再利用します
- DBに情報がない場合にAIで情報を生成する仕組みを追加します
- AIの出力は、想定したJSON Schemaに合致するか検証してから扱います
- 成分名の一致に確信が持てない場合は、自動確定せず候補として提示します
- 出典URLが取得できることと、その出典が説明内容を裏付けていることは別です。出典内容の検証は段階的に追加します
- AI生成情報には「AI生成」と表示し、確認状況を誤解させないようにします
- 成分詳細には「AI生成日」と「最終編集日(手動)」を表示し、情報がいつ作られ、いつ人の手で直されたかを確認できるようにします

## セットアップ(開発環境)

必要なもの: Docker Desktop。AI機能の実装フェーズでは OpenAI API キーが必要になります

```bash
git clone git@github.com:Elu-72b/ura-label.git
cd ura-label
cp .env.example .env   # AI機能を実装する段階で、.env に必要な API キーを設定する
docker compose build
docker compose up
```

別のターミナルで、初期データを入れます。

```bash
docker compose exec web bin/rails db:seed
```

http://localhost:3100 を開きます。

## プライバシー

- 将来カメラ読み取りを実装する場合、画像を外部AI APIへ送信する前に、送信先・保存の有無・利用規約を確認し、画面上で利用者に説明します
- 成分表以外(顔・住所など)が写らないように撮影してください
- ログインせずに使う場合、検索した成分名などをアカウントにひもづけて保存しません
- ログインした場合に保存するのは、メールアドレス・パスワード(ハッシュ化して保存)・気になる成分・検索履歴(保存を選んだ場合のみ)です
- 検索履歴は、初期設定では保存しません。保存した履歴は1件ずつ、またはまとめて削除できます。退会すると、アカウントにひもづくデータをすべて削除します
- 撮影した画像は、検索履歴にも保存しません
